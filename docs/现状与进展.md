## 1. 这东西在做什么

### 1.1 数据流

```
┌─────────┐   ①发消息    ┌──────────────┐
│  你     │ ───────────► │   飞书服务器  │
│ (手机/PC)│              │ open.feishu.cn│
└─────────┘              └──────┬───────┘
                                │ ②事件推送（WebSocket 长连接）
                                ▼
                         ┌──────────────┐
                         │  bot.py      │  ③组装上下文（人设 + 历史 + 本条）
                         │  (你的电脑/  │
                         │   服务器)    │
                         └──────┬───────┘
                                │ ④HTTP POST /chat/completions
                                ▼
                         ┌──────────────┐
                         │  DeepSeek    │  ⑤返回文本
                         │  (或任意兼容 │
                         │   模型服务)  │
                         └──────┬───────┘
                                │
                         ┌──────▼───────┐
                         │  bot.py      │  ⑥调飞书 API 回复到原消息
                         └──────┬───────┘
                                │ ⑦
                                ▼
                          你看到回复
```

### 1.2 为什么是"长连接"

飞书支持两种收事件的方式：

| 方式 | 需要什么 | 适用 |
|---|---|---|
| HTTP 回调（Webhook） | **公网 IP + 域名 + HTTPS 证书 + 处理 challenge 验证** | 生产环境、多实例 |
| 长连接（WebSocket） | 只要能出网 | **个人项目、内网机器、本机开发** ← 我们选这个 |

选长连接的直接后果：**服务器不需要公网 IP、不需要备案域名、不需要配 HTTPS**。你的程序主动连出去，事件从那根连接流回来。

代价是：同一应用只能跑一份实例（详见 §5）。

### 1.3 三个组件

| 组件 | 角色 | 你要管的 |
|---|---|---|
| 飞书自建应用 | 身份 + 消息通道 | 权限、事件订阅、发版 |
| `bot.py` | 你的程序，跑在电脑/服务器上 | 部署、进程存活 |
| 模型服务 | 生成回复 | API Key、余额 |

## 4. 关键决策记录

记下"为什么这么选"，避免以后重复纠结。

| 决策 | 选择 | 理由 |
|---|---|---|
| 推送渠道 | 飞书自建应用 | 个人可自建、无需提审、主动推送额度宽松；Telegram 需代理，QQ 官方机器人要审核+额度、协议端有封号风险 |
| 收消息方式 | 长连接 | 免公网 IP、免域名、免证书（原 ntfy 方案已废弃并清理） |
| 飞书 SDK | `lark-oapi` 官方 SDK | 长连接的握手/心跳/重连/解密手写成本高、易错 |
| 模型协议 | OpenAI 兼容 | DeepSeek/通义/Moonshot/Ollama 都能用，改 `LLM_BASE_URL` 即可切换 |
| 历史存储 | 内存 | 先跑通闭环；持久化列在路线图 P3 |
| 并发模型 | 线程池 + 每会话锁 | 事件回调必须立刻返回；同会话串行保住上下文 |
| 单条上限 | 3500 字拆条 | 飞书文本消息有大小限制，留安全余量 |

## 5. 已知限制（明确知道，暂未处理）

| 限制 | 影响 | 计划 |
|---|---|---|
| **只能跑一份实例** | 本地和服务器同时跑，飞书会把事件随机分给其中一条 → 时好时坏、日志对不上 | 部署后停掉本地，见 §6.3 |
| 历史只在内存 | 重启即清空；换服务器丢失历史 | P3 |
| 日志含消息正文 | 私密内容会落盘 | 需要时加脱敏开关 |
| 仓库是**公开**的 | 代码可见（无密钥）；暴露 App ID 使用方式 | 建议改 Private |
| 无主动推送 | 机器人不能主动找你 | P2 |
| 非文本消息 | 图片/文件/富文本一律回"只接文字" | P3 |
| 无限流 | 高频消息只靠 4 线程排队，未做队列背压 | 需要时再加 |
| 单进程 | 进程崩溃靠 systemd 拉起；持续调用失败无告警 | P1 |
| 无管理面板 | 改人设/模型要改 `.env` 并重启 | 暂不需要 |

### 8.3 故障排查

| 现象 | 排查顺序 |
|---|---|
| 服务起不来 | `journalctl -u feishu-bot -n 50` → 多半是 `.env` 缺失或填错 |
| 运行中但无响应 | ① 本地是否还有 `bot.py` 在跑 ② 开放平台订阅方式是否「长连接」 ③ 事件 `im.message.receive_v1` 是否已加且已发版 |
| 报 `230013` | 发送权限未开，或权限变更后未重新发版 |
| 报 `invalid app_secret` | `.env` 的 Secret 复制时带了空格或换行 |
| 首次私聊无响应 | 需先在飞书里主动给机器人发一条消息建立会话 |
| `$'\r': command not found` | 脚本被 CRLF 污染：`sed -i 's/\r$//' deploy/install.sh` |
| 中文乱码 | 检查 `PYTHONIOENCODING=utf-8`（systemd 已设） |

## 9. 安全与隐私

| 项 | 现状 | 建议 |
|---|---|---|
| `.env` | 本地存在，未入库（已扫描确认） | 服务器上 `chmod 600` |
| App Secret 泄露后果 | 他人可冒充你的机器人收发消息 | 泄露后在开放平台重置，然后改 `.env` 重启 |
| LLM Key 泄露后果 | 他人可消耗你的额度 | 在模型服务商后台吊销重建 |
| 仓库可见性 | **公开** | 改 Private：Settings → Danger Zone → Change visibility |
| 日志 | `bot.log` 含消息正文 | 敏感场景加脱敏或调高日志级别 |
| 群聊 | 默认需 @ 才回复 | 保持该设置，避免刷屏 |

**密钥轮换流程**：开放平台重置 Secret → 更新本地和服务器 `.env` → `systemctl restart feishu-bot`。App ID 不变，不需要重新发版。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| **SDK** | 软件开发工具包。这里指 `lark-oapi`，把飞书的鉴权、长连接、API 调用封装成函数 |
| **API** | 接口。飞书服务器提供的 HTTP 端点，SDK 底层调的就是它 |
| **长连接** | 一条持续打开的 WebSocket，服务器主动推事件给你，不用你轮询 |
| **事件（event）** | 飞书主动通知"发生了某事"，如"收到消息" |
| **`open_id`** | 用户在某个应用内的唯一 ID，跨应用不同 |
| **`chat_id`** | 会话 ID，单聊和群聊各有一个 |
| **scope / 权限** | 应用能调哪些 API 的授权，在开放平台勾选 |
| **`tenant_access_token`** | 应用身份的访问令牌，约 2 小时过期，SDK 自动刷新 |
| **幂等** | 同一请求发多次结果相同。这里用户发消息带 `uuid` 防止重复回复 |
| **systemd** | Linux 的服务管理器，负责开机自启、崩溃重启 |
| **venv** | Python 虚拟环境，把依赖隔离在项目内 |
